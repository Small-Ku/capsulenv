# Test DAG convergence — 2026-09-06

## Boundary

The canonical `scripts/Test-Capsulenv.ps1` gate keeps static analysis and the real Windows PowerShell 5.1 contract as release prerequisites, then schedules isolated Pester suites through a small Kahn-style DAG. The test DAG is deliberately narrower than the product desired-state DAG: its nodes are a shared test-module build, isolated suite processes, and a terminal barrier. Suite assertions, timeouts, temporary roots, build roots, result files, and failure accounting remain process-isolated.

The shared module build is a real data dependency rather than an implicit optimization. Functional suites consume the immutable prebuilt `Capsulenv.psm1` through child-process environment only. Suites whose purpose is to verify build/install/text-resource semantics keep their own local builds and do not rely on the shared artifact for the behavior under test.

Successful suite stdout/stderr is drained continuously and retained per suite instead of being multiplexed onto the parent console. The parent prints completion summaries; failure or infrastructure-error output is surfaced together with its artifact path. This avoids terminal rendering/backpressure from becoming a scheduling resource.

## Ablation

A sequential 30-suite baseline accumulated about 106.4 seconds of suite-process wall time. Blind 6-way parallelism produced long-tail stalls; 3-way and 4-way scheduling remained stable, with 4 as the current default throttle knee. The first DAG scheduler reduced the Full Pester phase to about 38.9 seconds. Reusing one immutable module build for functional suites reduced the validated Full Pester phase further to 35.77 seconds while eliminating roughly 28 redundant module merges.

Static analysis was profiled separately. PSScriptAnalyzer file analysis and custom AST rules each account for roughly half of its cost. Directory batching and multi-process PSScriptAnalyzer sharding did not improve wall time and were rejected. Reusing worker-safety findings across desired-state roots did improve both the analyzer and ArchitectureAnalysis suite and was retained. Static analysis is not currently overlapped with the Pester worker pool because resource-weighted experiments increased contention instead of reducing wall time.

## Validation

On PowerShell 7.6.5 with Pester 6.1.0 and PSScriptAnalyzer 1.25.0:

- static analysis: 70 files, 0 PSScriptAnalyzer diagnostics, 0 architecture violations;
- Fast: 143/143 passed;
- Full: 30 suites, 289/289 passed, 0 failed, 0 not run, 0 infrastructure failures; Pester DAG 35.77 s;
- Concurrency: 5 suites x 3 repeats, 210/210 passed, 0 infrastructure failures; Pester DAG 29.41 s;
- ArchitectureAnalysis: 69/69 passed.

The real Windows PowerShell 5.1 runtime contract remains a Windows-host release gate and cannot be executed on the Linux validation host.

## Converged rule

Use DAG parallelism only where isolation/resource evidence supports it. A data-producing prerequisite is an explicit edge; terminal completion is an explicit join; completion atomically consumes its ready token. Do not replace the scheduler with fixed waves, do not raise the default throttle merely because more logical CPUs exist, and do not overlap CPU-heavy static analysis with Pester workers without new measurements showing a net wall-time benefit.
